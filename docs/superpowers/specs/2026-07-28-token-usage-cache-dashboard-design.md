# Token 用量缓存与 Dashboard 交互设计

## 背景

Codex Radar 当前在首次监控和手动刷新时完整扫描
`~/.codex/sessions/**/*.jsonl` 与 `~/.codex/archived_sessions/**/*.jsonl`。在本机
约 1,905 个文件、2.24 GiB 日志的规模下，每次刷新都会重复读取和解析全部内容。
扫描虽然运行在 detached task 中，但持续的磁盘 I/O、解析与随后发布的大型事件数组
仍会让应用表现卡顿。

`TokenUsageView` 还在每次 SwiftUI 求值时从全部 `TokenUsageEvent` 重新生成分桶，
顶部指标则始终汇总全部历史事件。日、月、年选择器只改变柱状图分桶，不改变顶部指标，
筛选语义因此不完整。柱状图下方的逐行明细也重复呈现图表数据，并使卡片过长。

## 目标

- 有有效缓存时，Dashboard 在 300 ms 内显示 Token 用量。
- 缓存结果允许短暂陈旧；显示后在后台检查日志变化并自动更新。
- 后台刷新不阻塞主线程，未变化的 JSONL 文件不重复解析。
- 日、月、年分别让顶部指标表示今天、本月和今年。
- 柱状图分别展示最近 14 日、12 个自然月和 6 个自然年。
- 删除逐行明细，改为鼠标悬浮时显示对应柱的紧凑信息。
- 从界面移除 Cached 指标，只展示 Total、Input 和 Output。
- 保持现有 Token 解析与跨文件 session 去重口径。

## 非目标

- 不引入 SQLite 或其他数据库。
- 不增加实时文件系统监听。
- 不增加自定义日期范围。
- 不改变 Token 事件解析、累计快照或 stable session identity 规则。
- 不在 Dashboard 或悬浮提示中展示 Cached。

## 方案选择

### 采用：文件级解析缓存与展示快照

使用 macOS `Caches` 目录保存两个版本化文件：

1. 小型展示快照，供启动路径立即读取。
2. 后台 manifest，保存文件指纹、session identity 与文件解析结果。

刷新时先比较文件元数据，只有新增或变化的文件才重新解析。该方案无需新增运行时依赖，
能够消除重复读取大部分日志的成本，并让首屏读取与 manifest 大小解耦。

### 未采用：SQLite 索引

SQLite 能提供更强的增量查询、事务和长期扩展能力，但需要数据库 schema、迁移、
查询层及更多故障恢复测试。当前只有三种固定时间粒度，复杂度与收益不匹配。

### 未采用：只缓存最终汇总

仅缓存展示数据可以改善首屏，但后台仍会在每次启动和刷新时读取 2.24 GiB 日志，
没有消除持续 I/O 与解析开销。

## 架构与职责

### `TokenUsageRepository`

新增后台 actor，作为 Token usage 数据管线的唯一协调者：

- 加载并发布缓存快照。
- 枚举日志文件并生成当前 manifest。
- 比较文件指纹并安排必要的单文件解析。
- 合并文件结果并执行全局去重。
- 按当前时区生成展示快照。
- 协调并发刷新，防止旧结果覆盖新结果。
- 请求 `TokenUsageCacheStore` 持久化成功结果。

Repository 不依赖 SwiftUI，也不在主 actor 上执行文件 I/O 或解析。

### `TokenUsageCacheStore`

只负责缓存格式和磁盘 I/O：

- 从标准 macOS `Caches` 目录读取 snapshot 与 manifest。
- 校验 schema version、parser version 和必要字段。
- 通过同目录临时文件与原子替换写入完整文件。
- 把缺失、损坏或不兼容缓存报告为可恢复的 cache miss。

缓存是可重建数据，不进入 `Application Support`，也不成为统计权威来源。

### `CodexSessionScanner`

保留现有日志发现与解析职责，但拆出可独立测试的单文件解析入口。Repository 使用该入口
只解析新增或变化文件。Scanner 不管理磁盘缓存、SwiftUI 状态或刷新生命周期。

### `TokenUsageSnapshot`

新增不可变、`Sendable` 的 UI 快照，包含：

- 日、月、年三套已排序分桶。
- 今天、本月、今年各自的 Total、Input 和 Output。
- 是否存在任何可展示 Token 事件。
- 快照时区、生成时间与缓存格式需要的身份信息。

Total 继续等于 Input 加 Output。`cachedInputTokens` 仍保留在内部解析结果与去重身份中，
但不进入展示快照。

### `DashboardStore` 与视图

`DashboardStore` 不再向视图发布全部 `TokenUsageEvent`，改为发布
`TokenUsageSnapshot` 与独立的刷新、错误状态。`TokenUsageView` 和菜单栏只读取快照，
不在 SwiftUI `body` 求值期间遍历全部事件。

## 缓存模型

### Snapshot

Snapshot 是首屏专用的小文件，只包含三套固定窗口分桶和当前周期指标。它记录：

- cache schema version；
- parser version；
- 时区 identifier；
- 生成时间；
- 日、月、年展示数据。

启动时只读取该文件。时区一致且结构有效时立即发布；时区不一致时，Repository 使用
manifest 中的解析结果重新聚合，不重读原始 JSONL。

### Manifest

Manifest 在后台读取，每个文件记录：

- 规范化路径；
- 可用时的文件 resource identifier；
- 文件大小；
- 高精度修改时间；
- 解析得到的 session identity；
- 该文件的 Token 事件。

文件指纹由 resource identifier、路径、大小和修改时间共同判断。resource identifier
允许识别 active session 移入归档目录的常见场景；无法取得该标识时退化为路径与文件
元数据比较。

Manifest 与 snapshot 均包含独立版本号。parser 行为或缓存结构变化时整体失效并重建，
不对不兼容格式执行部分迁移。

## 数据流

### 启动

1. `DashboardStore` 请求 Repository 启动 Token usage 管线。
2. Repository 读取小型 snapshot。
3. snapshot 有效且时区匹配时立即发布，使 Dashboard 和菜单栏显示缓存值。
4. Repository 在后台读取 manifest、枚举两个日志根目录并比较文件指纹。
5. 只解析新增或变化文件；未变化文件复用已有解析结果。
6. Repository 合并所有文件结果，按现有 stable session identity 规则全局去重。
7. Repository 生成当前时区下的新快照并发布。
8. Cache Store 原子写入新 manifest，再写入新 snapshot。

解析文件前后都读取一次指纹。活跃日志在解析期间继续写入时，本轮结果不得作为该文件的
新缓存记录；Repository 最多立即重试一次，仍变化则保留旧记录并等待下次刷新，避免把
不完整内容标记成最新状态。

快照写在 manifest 之后。任一步骤中断时，已有 snapshot 仍只是允许陈旧的展示缓存；
下一次后台校验会重新收敛到磁盘日志状态。

### 手动刷新

手动刷新强制重新枚举全部文件和读取元数据，但仍只重新解析新增或变化文件。重复刷新被
Repository 合并；任何较早 generation 的异步结果都不得覆盖较新结果。

### 文件变化

- 未变化：复用 manifest 记录。
- 新增：解析并加入 manifest。
- 修改：完整重读该文件并替换旧解析结果。
- 移动到归档：通过 resource identifier 复用解析结果并更新路径。
- 删除：从 manifest 移除，随后重新执行全局去重和聚合。

本设计不做 JSONL 字节偏移续读。变化文件通常是当前活跃会话，完整重读单个文件比维护
可恢复 parser checkpoint 更简单可靠。

## 错误处理

- snapshot 缺失、损坏或版本不兼容：忽略并后台全量重建。
- manifest 缺失、损坏或版本不兼容：保留可用 snapshot 供展示，同时全量重建后台缓存。
- 已缓存文件暂时读取或解析失败：保留上次解析结果且不更新其指纹，并显示非阻塞警告，
  后续刷新重试。
- 新文件读取或解析失败：本轮跳过并显示非阻塞警告，后续刷新重试。
- 日志根目录不存在时按空目录处理；目录存在但枚举失败时保留现有快照与 manifest，
  不把暂时不可访问误判为删除。
- 缓存写入失败：保留本次内存快照并报告非阻塞警告；下次启动可能再次执行更多解析。
- 单次文件失败不阻止其他文件更新，也不清除最后一次成功快照。

## Dashboard 交互

### 周期与指标

选择器保留日、月、年三个选项。选择变化时同时更新顶部指标和图表：

| 选择 | 顶部指标口径 | 图表窗口 |
| --- | --- | --- |
| 日 | 今天 | 最近 14 个自然日 |
| 月 | 本月 | 最近 12 个自然月 |
| 年 | 今年 | 最近 6 个自然年 |

三个窗口都以当前自然周期为最后一项，生成连续分桶并补齐中间的零值周期；不再使用
“最后 14、12 或 6 个有数据的周期”。只有完全不存在 Token 事件时才显示空数据状态。

顶部改为三张等宽卡片：Total、Input、Output。当前自然周期没有事件时三项均显示零，
不得回退到全部历史值。

### 图表悬浮

删除柱状图下方的逐行明细。鼠标在绘图区移动时：

- 根据横坐标选择最近的可见柱；
- 高亮该柱并显示轻量定位线；
- 在柱旁显示周期日期、Total、Input 和 Output；
- 数值沿用现有紧凑近似格式；
- 浮层接近图表边缘时自动调整方向；
- 鼠标离开绘图区后清除选择与浮层。

悬浮信息不显示 Cached。空数据状态继续使用现有 `ContentUnavailableView`。

### 无障碍

删除明细行后，每根柱必须提供包含周期日期、Total、Input 和 Output 的 VoiceOver
标签与值。悬浮不是访问柱明细的唯一方式。周期选择器和三张指标卡继续使用系统控件与
本地化文本。

## 性能与生命周期

- 有有效 snapshot 时，Token 区域目标在 300 ms 内显示。
- snapshot 读取与发布不等待 manifest 解码、文件枚举或日志解析。
- 所有磁盘 I/O、解析、去重和聚合均在主 actor 外执行。
- Dashboard 与菜单栏接收小型快照，不持有或反复计算完整事件数组。
- 纯缓存刷新只读取文件元数据，解析文件数必须为零。
- 首次无缓存仍需全量扫描，但界面保持可交互并显示现有加载状态。
- 不增加常驻文件监听；更新仍由应用启动和手动刷新触发。

## 测试策略

### 缓存与 Repository

- snapshot 和 manifest 的命中、缺失、损坏及版本失效。
- 时区一致时立即发布 snapshot；时区变化时从 manifest 重新聚合。
- 未变化文件不调用 parser。
- 新增、修改、移动和删除文件正确更新 manifest 与快照。
- 活跃文件在解析期间变化时不提交不稳定指纹，并按限定次数重试。
- active 与 archived 的重复 session 保持现有去重结果。
- 已缓存文件失败时保留旧结果，新文件失败时跳过并重试。
- 缓存写入失败不丢失内存快照。
- 重叠刷新被合并，旧 generation 不能覆盖新 generation。
- 日志根目录不存在时按空集合处理，目录枚举失败时不清空统计。

### 聚合

- 日、月、年分别返回今天、本月和今年的三项指标。
- 图表分别生成连续的 14 日、12 月和 6 年窗口，并补齐零值周期。
- 当前周期无事件时返回零。
- 完全没有事件时显示空数据状态，而不是仅显示零值柱。
- 覆盖自然日、月末、年末、闰年、时区与夏令时边界。
- Total 始终等于 Input 加 Output。
- `cachedInputTokens` 不进入展示快照，但仍参与既有事件身份判断。

### UI 与无障碍

- 周期切换同时更新指标卡和图表数据。
- 视图只包含 Total、Input 和 Output，不包含 Cached 卡片。
- 不再渲染逐行明细区域。
- 鼠标移动选择最近柱，浮层显示正确日期和三项紧凑值，离开时清除。
- 图表边缘浮层不被裁切。
- 每根柱提供完整 VoiceOver 描述。
- Light/Dark Mode、中英文和最小窗口宽度下人工检查布局。

### 性能验证

单元测试通过可注入的文件枚举器和 parser 记录解析次数，证明纯缓存刷新不解析文件。
CI 不使用容易受机器负载影响的 300 ms 硬断言。发布前在本机约 1,905 个文件、
2.24 GiB 日志上测量：

- 有缓存时的首屏显示时间；
- 无变化手动刷新的解析文件数；
- 单个活跃文件变化后的刷新时间；
- 后台刷新期间窗口滚动、周期切换和菜单操作的响应性。
