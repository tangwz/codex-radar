# Dashboard 重置历史时间范围设计

## 目标

在已经确认的 Dashboard “Focus flow” 单列结构中，为月度重置柱状图增加
`3M / 6M / 12M / All` 时间范围切换。切换只影响月度图表，不改变本周、本月、
最近五次重置或 Token 用量的语义。

本设计是
`2026-07-19-reset-history-monthly-statistics-design.md`
的增量规格。它只覆盖旧规格中的固定滚动十二个月和无范围切换约束；服务端权威历史、
自然周/月、最近五条、永久保留和客户端无持久化 history cache 等规则保持不变。

## 已确认的视觉方向

Dashboard 保持由上至下的主要阅读流：

1. 下次重置预测卡片，副信息显示最近一次重置时间。
2. 本周、本月两个统计卡片。
3. 全宽月度重置柱状图，时间范围分段控件位于标题区右侧。
4. 最近五次重置的紧凑列表。
5. 现有完整 Token 用量区域。

Token 用量继续全宽展示。现有 `TokenUsageView` 包含四项汇总、柱状图和明细列表，
本功能不把它压缩成侧栏摘要，也不重构 Token 用量信息架构。

月度图表标题区包含：

- 左侧：`Resets by month` 和当前可见日期范围。
- 右侧：`3M / 6M / 12M / All` 分段控件。
- 默认值：`12M`。
- Info 说明：月份按客户端 IANA 时区中的自然月统计。

`3M`、`6M`、`12M` 在可用宽度内完整排布。`All` 使用固定最小柱宽和横向滚动，
初次显示定位到最新月份，避免历史永久增长后压缩柱形与标签。

## 客户端范围模型

新增一个独立、可测试的范围类型：

```text
3m
6m
12m
all
```

Store 在进程内保存当前选择，应用启动后的默认值为 `12m`。这只是展示偏好和当前响应，
不是磁盘缓存；应用重启后重新使用 `12m`。

响应中的 `months` 始终是按时间升序排列的连续自然月 bucket。Presentation 根据当前选择
生成图表数据：

- `3m`：最后三个 bucket。
- `6m`：最后六个 bucket。
- `12m`：最后十二个 bucket。
- `all`：响应中的全部 bucket。

响应新增 `range` 字段，回显服务端实际采用的规范化范围；省略请求参数时仍回显
`"12m"`。客户端继续验证月份 ID 唯一、严格连续、自然月边界正确，以及最后一个
bucket 与 `current.month` 的 `from`、`to`、`count` 完全一致。月份数量不再固定为
十二；固定范围必须与响应 `range` 一致，`all` 至少包含当前月。

## 请求策略

Dashboard 首次活动时仍只发起一次 history 请求，省略 `range` 或显式请求 `12m`：

```http
GET /v1/history?time_zone=Asia%2FShanghai
```

客户端复用已有十二个月响应完成 `3M / 6M / 12M` 切换，不增加网络请求。

第一次选择 `All` 且当前内存响应不是全量范围时，请求：

```http
GET /v1/history?time_zone=Asia%2FShanghai&range=all
```

成功后，当前全量响应也可在本地派生 `3M / 6M / 12M`。客户端不维护多个范围的响应缓存，
只保留最后一次成功的完整响应。

Dashboard 后续自动或手动刷新使用以下规则：

- 当前选择为 `all`：请求 `range=all`。
- 当前选择为 `3m`、`6m` 或 `12m`：请求默认 `12m`，再在本地裁剪。
- Dashboard 不活动时仍不请求 `/v1/history`。
- 时区变化、自然周/月边界、新 reset 到达和总刷新沿用原触发规则，并使用上述范围。

选择 `All` 的请求与现有 generation 机制共用取消和乱序隔离。快速切换范围时，
过期响应不得覆盖较新的选择或时区。

## 加载与错误状态

`3M / 6M / 12M` 的本地切换立即完成，不显示加载状态。

首次加载 `All` 时：

- 分段控件立即显示 pending 的 `All` 选择。
- 保留当前柱状图并降低强调度，在图表标题区显示紧凑进度指示。
- 本周、本月、最近五条和 Token 用量保持可读，不进入全页 loading。
- 请求成功后替换月份数据并将横向滚动定位到最新月份。
- 请求失败时恢复先前已提交的范围和图表，保留有效数据并显示非阻断错误。

首次 Dashboard history 请求失败时，继续使用原有独立错误空态和重试入口。

## 服务边界

`ResetHistoryService` 增加可选范围参数并按以下方式构造 URL：

- 默认十二个月可省略 `range`，以兼容已经部署的服务。
- 全量范围发送 `range=all`。
- 服务层拒绝未知范围或无法构造的请求。
- 服务层验证响应 `range` 与实际请求的规范化范围一致。

`ResetHistoryStore` 负责当前范围、pending 范围、请求 generation 和最后成功响应。
`ResetHistoryPresentation` 负责裁剪月份、日期范围文案、All 的横向图表数据和辅助功能摘要。
View 只绑定 presentation 和触发选择，不自行推断请求需求。

## 后端依赖

后端 follow-up 规格为：

```text
codex-radar-backend/docs/superpowers/specs/2026-07-23-reset-history-range-design.md
```

客户端发布依赖后端先支持可选 `range` 参数。旧后端仍支持默认十二个月请求，但会拒绝
`range=all`；因此不能先发布带有可用 `All` 控件的新客户端。

## 验证

### 模型与解码

- 接受连续的 3、6、12 和多于 12 个自然月 bucket。
- 解码并验证响应 `range`；固定范围的 bucket 数必须匹配。
- 拒绝空 `months`、月份重复、非升序、月份空洞和自然边界错误。
- 验证最后一个 bucket 与 `current.month` 完全一致。
- `all` 空历史响应仍包含当前月零值 bucket。

### 服务与 Store

- 默认请求只包含 `time_zone`。
- 首次选择 `All` 发送一次 `range=all`。
- 已加载全量响应后在四个范围间切换不重复请求。
- `3M / 6M / 12M` 从十二个月或全量响应正确裁剪。
- Dashboard 隐藏、时区变化、快速切换、手动刷新和 reset-change reload 不提交过期响应。
- All 加载失败保留旧图表并恢复已提交选择。

### 视图

- 分段控件默认选中 `12M`，支持键盘和 VoiceOver。
- `3M / 6M / 12M` 无标签重叠。
- `All` 使用固定最小柱宽、横向滚动并初始定位最新月份。
- Light/Dark Mode、中英文、窄窗口和大量月份人工检查通过。
- Token 用量继续以现有全宽结构展示。

## 非目标

- 不增加完整事件历史、cursor 分页或加载更多。
- 不增加自定义起止日期或任意月份数。
- 不增加客户端磁盘缓存。
- 不改变本周、本月、最近五条和重置事件计数口径。
- 不在本功能中增加环比、平均间隔或最长间隔。
