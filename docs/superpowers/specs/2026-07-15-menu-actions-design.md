# 菜单栏操作区重设计

## 目标

将 Codex Radar 菜单栏弹窗底部现有的不一致按钮与链接，重构为紧凑、统一、符合 macOS 习惯的菜单列表。视觉参考 CodexBar：图标、标题与快捷键在稳定列上对齐，整行可点击，使用系统 hover 和 disabled 状态，不改变现有业务行为。

## 信息层级与顺序

操作区固定按以下顺序显示：

1. 打开预测来源
2. 分隔线
3. 打开仪表盘，快捷键为 Command-D
4. 立即检查，快捷键为 Command-R
5. 设置…，快捷键为 Command-,
6. 退出，快捷键为 Command-Q

预测来源作为与当前 reset 信息直接相关的上下文操作，独立放在分隔线之前。应用级操作位于分隔线之后，不再为退出操作额外增加第二条分隔线。

## 视觉设计

每个操作使用统一的 `MenuActionRow`：

- 左侧为固定宽度的 SF Symbol 图标列。
- 中间为单行标题，使用系统正文样式。
- 右侧为次要色快捷键提示；预测来源使用外链箭头。
- 行高保持紧凑，整行拥有一致的水平内边距和点击区域。
- 默认背景透明；鼠标悬停时显示系统自适应的浅色圆角高亮。
- 不再使用各自独立的灰色按钮底色，也不使用蓝色 Link 文本。
- 颜色全部采用系统语义色，继续适配 Light Mode、Dark Mode 和中英文。

## 交互行为

- 打开预测来源：使用系统默认浏览器打开当前 forecast 的来源 URL。
- 打开仪表盘：打开现有 dashboard window，并将应用激活到前台。
- 立即检查：执行现有 refresh；刷新期间禁用该行，并在右侧显示小型进度指示器。
- 设置：打开现有 Settings scene。
- 退出：终止 Codex Radar。
- 快捷键需要在菜单栏弹窗聚焦时可用，同时右侧提示与真实绑定保持一致。

## 代码范围

- 修改 `Sources/CodexRadar/Views/MenuBarView.swift`。
- 如新增可复用行组件，保持为该文件内的私有 SwiftUI view，避免为单一使用场景增加额外模块。
- 复用现有本地化键；将退出标题从“退出 Codex Radar”缩短为“退出”时补充中英文资源。
- 不修改 Dashboard、store、reset 数据源、token 扫描或通知逻辑。
